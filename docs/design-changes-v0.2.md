# 设计变更 v0.2（面向 100 GB 级语料，2026-11-03）

背景：需求文档按 2–4 GB 文档设计；用户确认目标规模约 100 GB，且不更换 Embedding 模型（bge-m3，1024 维）。
依据：`docs/poc-results-2026-11-03-realdocs.md`（17 个真实文档、21 题实测）。

## 1. 向量存储：二值粗筛 + int8 精排

| | v0.1 | v0.2 |
| --- | --- | --- |
| 存储 | 每块 float32 向量 4 KB | 二值向量 128 B（粗筛）+ int8 向量 1 KB（精排），按文本哈希去重 |
| 检索 | sqlite-vec 全表余弦 | 汉明距离取 200 个候选 → int8 余弦精排取前 30 |
| 100 万块（实测，云端 2 核） | — | 检索中位数 286 ms，进程内存 50 MB，向量部分数据库 1.55 GB |

- 语料规模估算：按 17 个样本文档的“文件大小 → 文本块”比例，100 GB 约 70 万–300 万块，3M 块时检索约 1 s。
- int8 采用每个向量单独缩放，余弦与缩放无关，精度损失可忽略（单元测试：与 float 余弦误差 < 0.01）。
- 召回：合成的 1024 维带簇向量上，与精确余弦 top-10 的重合率 ≥ 90%（单元测试）；真实文档的检索命中率由 `run_realdocs.command` 复测。
- 数据库格式升级为 schema v2，旧索引需删除重建（程序会检测并提示）。

## 2. Embedding 缓存与按块增量

- 向量按文本内容哈希存一份：重复的页眉页脚、模板页只计算一次。
- 修改文件时只为改动的文本块计算向量，未改动的块直接复用；不再被引用的向量在索引结束时清理。
- 每次索引记录复用块数、解析耗时、计算向量耗时，用于判断瓶颈。
- 批量从 16 提高到 32。

## 3. 语言处理：同语言加权（soft）

- 默认不再只检索同语言文本块，而是所有语言参与检索，同语言块在融合时分数乘以 1.2。
- 原因：实测硬过滤对同语言命中率没有提升（18/18 两种方式相同），但会排除中英混合文档里另一种语言的答案。
- `strict`（v0.1 行为）与 `all` 仍可通过配置或 `--lang-mode` 选择。
- 语言检测改为比较汉字数与英文单词数：实测夹带型号、模型名的中文段落曾被误判为英文。
- 范围说明：用户确认不会用中文问纯英文文档；soft 模式解决的是混合文档中换语言提问的问题。

## 4. 内存：4K 上下文、4 个片段

| | v0.1 | v0.2 |
| --- | --- | --- |
| 上下文 | 8,192 | 4,096（KV 缓存约 0.6 GB，减半） |
| 片段数 | 5 | 4 |
| 输出上限 | 1,024 | 512（实测回答多在 50 tokens 以内） |
| Ollama | 默认 | 建议 `scripts/ollama_tune.sh`：Flash Attention + 8 bit KV 缓存 |

- 实测 v0.1 配置下交换区从 2.4 GB 增长到 10.3 GB，首 token 中位数 8.1 s。
- 新增 `qwen3:1.7b` 作为对比候选（约 2.5 GB 运行占用，对 4B 约 4 GB），是否替换待对比结果决定。

## 5. 评测工具

- `lkos eval` 新增 `--model`、`--lang-mode`、`--out`（保存每题回答原文与引用）。
- `run_realdocs.command` v2：分阶段记录交换区与 `ollama ps`，对比 soft / strict 检索、4B / 1.7B 问答。
